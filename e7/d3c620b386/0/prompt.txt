<result>I'd call this **ready with fixes**. API usage is correct and the new tests pass, but there are five Important issues, and the first two, the CLI's database file and how `verify` records runs, need a design decision.

**Strengths**
- Every call into `@dailies/pipeline`, `@dailies/agent`, `@dailies/voice` and `@dailies/core` matches the real signatures (`buildStages`, `StageDeps`, `runPipeline`, `listEvents(db, runId, afterId)`, `CostMeter(limit)`, `createRouter(env, meter)`, `createGeminiTts(keys)`, `RenderArtifact`).
- **The `dailies-reel` span does carry the repo URL.** neatlogs' `decorateSpan` records input by default, and with one argument it writes that whole object as the span's `input.value`. So `{repoUrl: &lt;stripped&gt;, runId}` lands on the root span, and the workflow name matches what `memory.ts` filters on.
- **`--max-sessions` reaches ingest.** The ingest test pins newest-first with a cap of 1. Ingest's progress messages are fixed strings, so passing them to the run's log leaks nothing.
- **The voice fallback is tight.** Its test checks the exact captions artifact, one provider call, and that the error is logged.
- **The security fixes hold.** `sanitizeForTerminal` covers control, format and line/paragraph-separator characters and escapes backslashes. `stripUserinfo` makes a URL pass and then a regex pass, and fails closed.
- I re-ran the new tests: pipeline ingest and voice 14/14, CLI 9 passed and 1 skipped (the render test, filtered out on purpose). The tree is still clean.

**Important**
1. **The CLI uses a different database file from the web app.** `run.ts:132` and `verify.ts:70` open `&lt;dataDir&gt;/db.sqlite`. The already-merged web app (`apps/web/src/server/db.ts:16`, product plan line 89) uses `&lt;dataDir&gt;/dailies.db`, and spec §3 says there is one database. A CLI reel that ends `needs_approval` never shows up in `/inbox`. The README also says "a crash resumes from the last completed stage", but nothing resumes CLI runs. Simply switching files has a catch: the web worker's `unfinishedRuns` would then pick up CLI runs while they are still running, so decide that first.
2. **Every `verify` leaves a run marked `needs_approval` with no reel.** That is how `runPipeline` ends when given only ingest and verify. Using `openDb(':memory:')` in `verify.ts` would fix it, since verify doesn't need the run history.
3. **The CLI can silently do nothing and exit 0** (`index.ts:15`). It decides whether it was run directly by comparing `import.meta.url` with `file://${process.argv[1]}`. I confirmed this check fails when the path contains a space (the URL is percent-encoded) or sits under a symlink (`/tmp` → `/private/tmp` on macOS). Comparing `fileURLToPath(import.meta.url)` with `realpathSync(process.argv[1])` fixes it.
4. **`--max-sessions` isn't validated** (`run.ts:38`). A non-number or a missing value becomes NaN, `slice(0, NaN)` returns nothing, and the user gets "no agent sessions found in this window" with exit 2, which is the wrong diagnosis. A negative number quietly drops the newest sessions.
5. **The documented plugin flow can't find its config.** `loadEnv()` looks for `.env` in the current directory. `entire dailies run .` runs from inside the target repo, so it misses the `.env` at the Dailies root and stops with "LITELLM_API_KEY is not set". It also writes `.dailies/` (clones, database, renders) into the target repo. The CLI should pass its own repo root to `loadEnv`.

**Minor**
- `verify --json` skips sanitizing. `JSON.stringify` leaves C1 control and bidi-override characters intact.
- `--since 7` is read as a date in 2001, because `new Date()` accepts much more than ISO. A missing `--since` value silently becomes 24h, and unknown flags are taken as the repo argument.
- The voice fallback skips the runner's retries, so one transient network error goes straight to captions. Spec §8 says "retry, alternate voice, then captions". It follows the task's instruction, but it is a trade-off worth noting.
- `--out` also copies a reel that the gate blocked, which weakens the gate's fail-closed promise.
